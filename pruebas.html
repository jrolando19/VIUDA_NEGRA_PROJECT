Sistema de Testing

InvenTree mantiene un sistema de testing automatizado que cubre el backend Django, la API REST y los flujos críticos de negocio. Usa pytest como runner principal junto con el Django Test Framework. Cada módulo tiene su propio directorio de pruebas, y el pipeline de GitHub Actions ejecuta todos los tests automáticamente ante cada Pull Request.

Pruebas Unitarias

Verifican componentes individuales en aislamiento usando base de datos en memoria. Cada tarjeta muestra los escenarios cubiertos con link directo al código en GitHub.

📦 Módulo Part — Catálogo de Partes

~450 tests Ver tests en GitHub ↗ Ver models.py ↗

Verifica la lógica del catálogo de partes incluyendo reglas complejas como herencia de BOM entre variantes y detección de referencias circulares.

  • Creación de partes con validación de campos obligatorios y opcionales
  • Unicidad de nombre dentro de categoría — falla si hay duplicado
  • Herencia de parámetros desde plantillas de categoría
  • Cálculo de stock total disponible a partir de múltiples ubicaciones
  • Resolución de BOM en múltiples niveles (recursivo)
  • Detección de referencias circulares en BOM — debe lanzar error
  • Activación y desactivación de partes con validación de dependencias activas

📊 Módulo Stock — Control de Inventario

~380 tests Ver tests en GitHub ↗ Ver models.py ↗

Cubre todos los movimientos posibles de inventario y verifica la integridad de los datos de StockItem en cada estado del ciclo de vida.

  • Creación de StockItem con cantidad, ubicación y número de serie
  • Transferencia entre ubicaciones — historial registrado correctamente
  • División (split) de un item en múltiples cantidades
  • Fusión (merge) de items del mismo Part en una ubicación
  • Ajuste de cantidad con motivo obligatorio — falla sin motivo
  • Unicidad de serial por Part — no permite dos seriales iguales
  • Stock asignado vs disponible — no permite asignar más del disponible

🏭 Módulo Build — Órdenes de Manufactura

~290 tests Ver tests en GitHub ↗ Ver models.py ↗

Valida el ciclo completo de una orden de manufactura desde creación hasta finalización y su impacto en el stock de componentes.

  • Generación automática de requerimientos desde BOM al crear BuildOrder
  • Validación de disponibilidad de stock antes de iniciar — bloqueo si falta material
  • Consumo correcto de StockItems al completar la orden
  • Generación de StockItems de salida (producto terminado) al completar
  • Cancelación con devolución del stock previamente asignado
  • Builds en cascada para sub-ensamblajes anidados

🛒 Módulo Order — Órdenes de Compra y Venta

~310 tests Ver tests en GitHub ↗ Ver models.py ↗

Cubre el ciclo de vida completo de órdenes de compra (PO), ventas (SO) y devoluciones (Return Orders).

  • Creación de PO con líneas de detalle y asociación a proveedor
  • Recepción parcial de mercancía — stock actualizado correctamente
  • Transición de estados: borrador → emitida → recibida — validación en cada paso
  • Bloqueo al intentar recibir más unidades que las pedidas
  • Return Orders — devolución de stock con registro en historial
  • Historial de precios por proveedor actualizado al recibir

🔐 Autenticación y Permisos

~160 tests Ver tests.py en GitHub ↗

Prueba el sistema de autenticación y autorización garantizando que los permisos se aplican correctamente en todos los módulos.

  • Login con credenciales válidas — devuelve token de sesión
  • Login con credenciales inválidas — HTTP 401
  • Generación y revocación de tokens API Bearer
  • Acceso a endpoint sin permiso — HTTP 403 Forbidden
  • Superusuario con acceso irrestricto a todos los módulos
  • Bloqueo automático por intentos fallidos consecutivos

🧩 Sistema de Plugins

~120 tests Ver tests en GitHub ↗ Ver plugin.py ↗

Verifica la arquitectura de plugins: carga, registro, hooks y que un plugin defectuoso no derrumbe el sistema.

  • Carga de plugin válido — registrado correctamente en el sistema
  • Activación desde la interfaz de administración
  • Plugin con dependencias faltantes — falla con mensaje claro
  • Hooks de eventos (pre/post stock update) — ejecutados correctamente
  • Plugin defectuoso no interrumpe el funcionamiento del núcleo

Herramientas de Testing

🐍

pytest + pytest-django

Runner principal. El plugin pytest-django añade fixtures de BD, cliente de test y gestión de settings de Django.

Ver requirements.txt ↗
📊

coverage.py

Mide líneas ejecutadas durante los tests. Genera reportes HTML y XML, subidos automáticamente a Codecov.

Ver setup.cfg ↗
🔍

Flake8 + isort

Análisis estático. Flake8 valida PEP8 y complejidad ciclomática. isort ordena imports automáticamente.

Ver qc_checks.yaml ↗

Conclusiones del Análisis

  • Más de 2000 casos de test cubren todos los módulos críticos con cobertura promedio superior al 85%.
  • Cada módulo tiene su propio directorio de tests accesible directamente en el repositorio GitHub.
  • El pipeline de GitHub Actions valida automáticamente cada PR antes de permitir el merge.
  • La separación entre tests.py (unitarios) y test_api.py (integración) mantiene los tests organizados y enfocados.
  • Las pruebas de API verifican tanto casos de éxito como de fallo, asegurando que los errores devuelven los códigos HTTP correctos.
  • El sistema de testing facilita la contribución externa: cualquier colaborador puede correr la suite completa localmente antes de abrir un PR.
