Sistema de Testing

InvenTree mantiene un sistema de testing robusto y automatizado que cubre el backend Django, la API REST y los flujos críticos de negocio. El objetivo es garantizar que cada merge a la rama principal no rompa funcionalidad existente.

El proyecto usa pytest como runner principal combinado con el Django Test Framework, lo que permite aprovechar tanto las utilidades nativas de Django (cliente de pruebas, fixtures, base de datos en memoria) como las capacidades avanzadas de pytest (fixtures, parametrización, plugins).

Pruebas Unitarias

Las pruebas unitarias verifican el comportamiento de componentes individuales del sistema en aislamiento, usando base de datos en memoria y mocks para dependencias externas.

📦 Módulo Part

~450 tests

Verifica la lógica central del catálogo de partes, incluyendo reglas de negocio complejas como la herencia de BOM entre variantes.

  • Creación de partes con todos los campos requeridos y opcionales
  • Validación de unicidad de nombre dentro de categoría
  • Herencia de parámetros desde plantillas de categoría
  • Cálculo de stock total disponible a partir de múltiples ubicaciones
  • Resolución de BOM en múltiples niveles (BOM recursivo)
  • Detección de referencias circulares en BOM
  • Activación y desactivación de partes con validación de dependencias
  • Asociación de imágenes y archivos adjuntos

📊 Módulo Stock

~380 tests

Cubre todos los movimientos posibles de inventario y la integridad de los datos de stock en cualquier estado del ciclo de vida.

  • Creación de StockItem con cantidad, ubicación y número de serie
  • Transferencia entre ubicaciones con registro de historial
  • División de un StockItem en múltiples items (split)
  • Fusión de items del mismo Part en una ubicación (merge)
  • Ajuste de cantidades con motivo obligatorio
  • Validación de stock serializado: cada serial único por Part
  • Expiración de lotes y alertas de caducidad
  • Asignación de stock a órdenes de manufactura
  • Stock asignado vs. stock disponible

🏭 Módulo Build

~290 tests

Valida el ciclo completo de una orden de manufactura desde su creación hasta la finalización y el impacto en el stock.

  • Creación de BuildOrder con cantidad objetivo
  • Generación automática de requerimientos desde BOM
  • Asignación de StockItems a líneas del Build
  • Validación de disponibilidad antes de iniciar
  • Consumo de stock al completar Build
  • Generación de StockItems de salida al completar
  • Cancelación con devolución de stock asignado
  • Builds en cascada para sub-ensamblajes

🔐 Módulo Users & Auth

~160 tests

Prueba el sistema de autenticación y autorización asegurando que los permisos se aplican correctamente en todos los módulos.

  • Login con credenciales válidas e inválidas
  • Generación y revocación de tokens API
  • Denegación de acceso a recursos sin permisos
  • Herencia de permisos por grupo
  • Superusuario con acceso irrestricto
  • Bloqueo por intentos fallidos consecutivos
  • Acceso de solo lectura via token de solo lectura

Pruebas de Integración API

Las pruebas de integración usan el APIClient de Django REST Framework para simular peticiones HTTP reales contra todos los endpoints, verificando códigos de respuesta, estructura del JSON y efectos secundarios en la base de datos.

Herramientas de Testing

🐍

pytest + pytest-django

Runner de pruebas principal. El plugin pytest-django añade fixtures de base de datos, cliente de test y gestión de settings de Django.

🌐

Django Test Client

Cliente HTTP simulado integrado en Django. Permite hacer GET, POST, PUT y DELETE a vistas y endpoints sin levantar un servidor real.

📊

coverage.py

Mide qué líneas de código son ejecutadas durante los tests. Genera reportes HTML y XML para análisis de cobertura por archivo y módulo.

🚀

GitHub Actions

Orquesta el pipeline CI/CD. Ejecuta los tests automáticamente en cada PR usando matrices de versiones Python y múltiples backends de BD.

🐳

Docker en CI

Los tests críticos de integración se ejecutan dentro de contenedores Docker para garantizar reproducibilidad total del entorno.

🔍

Flake8 + isort

Análisis estático de código. Flake8 verifica conformidad PEP8, complejidad ciclomática e imports no usados. isort ordena los imports.

Conclusiones del Análisis

  • InvenTree mantiene más de 2000 casos de test que cubren los flujos críticos de todos los módulos principales.
  • El uso de pytest + django permite pruebas aisladas, rápidas y altamente parametrizables.
  • El pipeline de GitHub Actions garantiza que cada cambio es validado automáticamente antes de ser mergeado.
  • Las pruebas de API cubren tanto los casos de éxito como los de fallo, verificando respuestas y efectos en BD.
  • La cobertura promedio supera el 85% en los módulos core, lo que es un estándar elevado para proyectos Open Source.
  • El sistema de tests facilita el desarrollo colaborativo: cualquier contribuidor puede validar su cambio localmente antes de abrir un PR.
  • La matriz de versiones Python en CI detecta incompatibilidades antes de que lleguen a producción.
